## 2. Environment Configuration & Credential Setup

Before running any service, you must configure Safaricom Daraja API credentials, generate cryptographically secure seed passwords, and understand the environment variable layout.

### Step 2.1: Clone the Repository
```bash
git clone https://github.com/odjustingabriel/OpenFloat-M-Pesa-Middleware-Platform.git
cd OpenFloat-M-Pesa-Middleware-Platform
```

### Step 2.2: Obtain Safaricom Daraja Sandbox Credentials
1. Register for a Daraja developer account at [https://developer.safaricom.co.ke](https://developer.safaricom.co.ke).
2. Create a new **Lipa Na M-Pesa Online (STK Push)** sandbox application.
3. From your Daraja dashboard, copy the following values:
   * **Consumer Key** — Used for OAuth2 token generation
   * **Consumer Secret** — Paired with Consumer Key for authentication
   * **Passkey** — Required for computing the LNMO password (`Base64(Shortcode + Passkey + Timestamp)`)
   * **Shortcode** — The sandbox paybill number (default: `174379`)

### Step 2.3: Generate Seed Passwords & Encryption Keys
```bash
bash scripts/rotate-seed-passwords.sh
```
This script generates cryptographically secure 32-character base64 values for database passwords, Redis auth tokens, JWT signing secrets, and the AES-256 master encryption key. Output is written to `.env` and `.env.production`.

### Step 2.4: Configure the `.env` File
After running the password rotator, update the generated `.env` file with your Daraja credentials:

```dotenv
# ── Safaricom Daraja API Credentials ──────────────────────────
MPESA_CONSUMER_KEY=your_consumer_key_here
MPESA_CONSUMER_SECRET=your_consumer_secret_here
MPESA_PASSKEY=bfb279f9aa9bdbcf158e97dd71a467cd2e0c893059b10f78e6b72ada1ed2c919
MPESA_SHORTCODE=174379
MPESA_BASE_URL=https://sandbox.safaricom.co.ke

# ── Database ──────────────────────────────────────────────────
POSTGRES_DB=openfloat_db
POSTGRES_USER=openfloat
POSTGRES_PASSWORD=<auto-generated>

# ── Redis ─────────────────────────────────────────────────────
REDIS_PASSWORD=<auto-generated>

# ── Security ──────────────────────────────────────────────────
OPENFLOAT_ENCRYPTION_KEY=<auto-generated-256-bit-base64-key>
JWT_SIGNING_SECRET=<auto-generated>

# ── RabbitMQ ──────────────────────────────────────────────────
RABBITMQ_DEFAULT_USER=admin
RABBITMQ_DEFAULT_PASS=admin123!

# ── ERP Target (choose one: sap, oracle, dynamics, custom) ───
ERP_ACTIVE_ADAPTER=custom
ERP_TARGET_URL=http://localhost:9999/erp/webhook
ERP_API_KEY=test-api-key
```

### Step 2.5: Spring Boot Profile Activation
The platform supports two Spring profiles:

| Profile | Activation | Purpose |
|---|---|---|
| `default` | No flag needed | Local development — connects to localhost infrastructure, Daraja sandbox URLs, Swagger-UI enabled |
| `prod` | `--spring.profiles.active=prod` | Production — enforces TLS 1.3, Vault secret lookups, Safaricom production URLs, Swagger-UI disabled |

To launch a service with the production profile:
```bash
cd openfloat-core
mvn spring-boot:run -Dspring-boot.run.profiles=prod
```

## 3. Method 1: Local Docker Compose Quick Start (Recommended)

The fastest way to launch the entire platform (all microservices, supporting databases, messaging queues, monitoring stack, and React frontend) is via Docker Compose.

1. **Launch Infrastructure & Application Containers:**
   ```bash
   docker compose up --build -d
   ```

2. **Verify Running Containers:**
   ```bash
   docker compose ps
   ```

   **Expected Services & Ports:**
   * **API Gateway (`openfloat-gateway`):** `https://localhost:8443`
   * **Staff Portal Frontend (`openfloat-staff-portal`):** `http://localhost:3000`
   * **OAuth2 Auth Server (`openfloat-auth`):** `http://localhost:8081`
   * **Core Service (`openfloat-core`):** `http://localhost:8080`
   * **ERP Connector (`openfloat-erp-connector`):** `http://localhost:8082`
   * **PostgreSQL Database:** `localhost:5432`
   * **Redis Cache & Rate Limiter:** `localhost:6379`
   * **RabbitMQ Management Console:** `http://localhost:15672` (User/Pass: `admin`/`admin123!`)
   * **Prometheus Metrics:** `http://localhost:9090`
   * **Grafana Monitoring Dashboard:** `http://localhost:3001` (User/Pass: `admin`/`admin`)
   * **Mailpit Email Stub:** `http://localhost:8025`

3. **Stop the Application Stack:**
   ```bash
   docker compose down
   ```

## 4. Method 2: Manual Local Microservice Execution

For active development, you may want to run infrastructure in Docker while executing microservices locally in your IDE or terminal.

### Step 4.1: Build Backend Monorepo
Compile and install all shared Maven modules (`openfloat-common`, `openfloat-core`, `openfloat-auth`, `openfloat-erp-connector`, `openfloat-gateway`):

```bash
mvn clean install -DskipTests
```

### Step 4.2: Start Infrastructure Services Only
Spin up PostgreSQL, Redis, RabbitMQ, Mailpit, Prometheus, and Grafana:

```bash
docker compose up -d postgres redis rabbitmq mailpit prometheus grafana
```

### Step 4.3: Launch Microservices (Open 4 Terminal Windows)

* **Terminal 1 — Core Payment Service (`openfloat-core`):**
  ```bash
  cd openfloat-core
  mvn spring-boot:run
  ```
  *(Starts on `http://localhost:8080` — initializes database schema via Flyway migrations)*

* **Terminal 2 — Authorization Server (`openfloat-auth`):**
  ```bash
  cd openfloat-auth
  mvn spring-boot:run
  ```
  *(Starts on `http://localhost:8081` — validates database schema created by core)*

* **Terminal 3 — ERP Connector Service (`openfloat-erp-connector`):**
  ```bash
  cd openfloat-erp-connector
  mvn spring-boot:run
  ```
  *(Starts on `http://localhost:8082`)*

* **Terminal 4 — API Gateway (`openfloat-gateway`):**
  ```bash
  cd openfloat-gateway
  mvn spring-boot:run
  ```
  *(Starts on `https://localhost:8443`)*

### Step 4.4: Launch Staff Portal Frontend

* **Terminal 5 — Staff Portal SPA (`openfloat-staff-portal`):**
  ```bash
  cd openfloat-staff-portal
  npm install
  npm run dev
  ```
  *(Vite Dev Server launches on `http://localhost:3000`)*

## 5. Method 3: Production Kubernetes Deployment

This section covers a full production deployment to a Kubernetes cluster.

### Step 5.1: Cluster Prerequisites
Ensure the following are installed and configured on your target cluster:

| Component | Purpose | Install Command |
|---|---|---|
| **NGINX Ingress Controller** | TLS-terminating reverse proxy | `kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/controller-v1.9.5/deploy/static/provider/cloud/deploy.yaml` |
| **cert-manager** | Automated Let's Encrypt TLS certificate provisioning | `kubectl apply -f https://github.com/cert-manager/cert-manager/releases/download/v1.14.4/cert-manager.yaml` |
| **Istio Service Mesh** | Internal mTLS enforcement between pods | `istioctl install --set profile=default -y` |
| **HashiCorp Vault** | External secrets engine for credential injection | Deployed via Helm: `helm install vault hashicorp/vault --namespace vault` |

Verify readiness:
```bash
kubectl get pods -n ingress-nginx
kubectl get pods -n cert-manager
kubectl get pods -n istio-system
```

### Step 5.2: Seed Production Secrets into Vault
Populate database credentials, Daraja API keys, JWT signing secrets, and AES-256 encryption keys into Vault KV-v2:
```bash
bash scripts/vault-seed-secrets.sh
```
This writes secrets to the following Vault paths:
* `secret/data/openfloat/database` — PostgreSQL `username`, `password`, `url`
* `secret/data/openfloat/daraja` — `consumerKey`, `consumerSecret`, `passkey`, `shortcode`
* `secret/data/openfloat/encryption` — AES-256-GCM master key
* `secret/data/openfloat/jwt` — RSA signing key pair

### Step 5.3: Apply Kubernetes Manifests (In Dependency Order)
```bash
# 1. Namespace & Configuration
kubectl apply -f k8s/namespace.yaml
kubectl apply -f k8s/configmap.yaml
kubectl apply -f k8s/secret.yaml

# 2. Infrastructure ConfigMaps
kubectl apply -f k8s/vault-agent-config.yaml
kubectl apply -f k8s/redis-ha-config.yaml
kubectl apply -f k8s/pod-resource-hardening.yaml

# 3. Observability & SIEM
kubectl apply -f k8s/logstash-config.yaml
kubectl apply -f k8s/prometheus-alerts.yaml

# 4. Network Security
kubectl apply -f k8s/gateway-ingress-tls.yaml
kubectl apply -f k8s/internal-mtls-policy.yaml

# 5. Application Deployments, Services, & HPA
kubectl apply -f k8s/

# 6. Daily Database Backup CronJob
kubectl apply -f k8s/postgres-backup-cronjob.yaml
```

### Step 5.4: Verify Pod Readiness & HPA
```bash
# Check all pods are Running
kubectl get pods -n openfloat -o wide

# Verify Horizontal Pod Autoscaler is configured
kubectl get hpa -n openfloat
# Expected: openfloat-core   min:2  max:10  target CPU: 70%

# Verify TLS certificate was issued
kubectl get certificates -n openfloat
# Expected: openfloat-tls-cert   True   (Ready)

# Verify Istio mTLS is enforced
kubectl get peerauthentication -n openfloat
# Expected: default-strict-mtls   STRICT
```

### Step 5.5: Run Automated Go-Live Verification
```bash
bash scripts/go-live-checklist-verify.sh
```
Expected output: `7/7 Checks Passed — PLATFORM GO-LIVE READY`

### Step 5.6: Validate Load Testing & HPA Scaling
Run the k6 load test to stress-test the gateway and trigger autoscaling:
```bash
k6 run --env TARGET_URL=https://api.openfloat.co.ke \
       --env TOKEN=${ADMIN_TOKEN} \
       scripts/k6-load-test.js
```
Monitor HPA scaling in a separate terminal:

```bash
curl -X POST http://localhost:8080/api/v1/payments/stk-push \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ${ADMIN_TOKEN}" \
  -d '{
    "msisdn": "254712345678",
    "amount": 100,
    "accountReference": "REF-TEST-001",
    "paybill": "174379"
  }'
```
**Expected Response (HTTP 202 Accepted):**
```json
{
  "status": "PENDING",
  "transactionId": "txn_abc123",
  "checkoutRequestId": "ws_CO_24072026123456789"
}
```

### 6.4: Simulate Daraja STK Callback
After initiating an STK Push in sandbox mode, simulate Safaricom's asynchronous callback:

```bash
curl -X POST http://localhost:8080/api/v1/mpesa/callbacks/stk \
  -H "Content-Type: application/json" \
  -d '{
    "Body": {
      "stkCallback": {
        "MerchantRequestID": "29123-10022-1",
        "CheckoutRequestID": "ws_CO_24072026123456789",
        "ResultCode": 0,
        "ResultDesc": "The service request is processed successfully.",
        "CallbackMetadata": {
          "Item": [
            { "Name": "Amount", "Value": 100 },
            { "Name": "MpesaReceiptNumber", "Value": "REC-RBS789XYZ" },
            { "Name": "TransactionDate", "Value": 20260724120000 },
            { "Name": "PhoneNumber", "Value": 254712345678 }
          ]
        }
      }
    }
  }'
```
**What happens internally:**
1. `MpesaCallbackController` receives the webhook and persists the raw JSON payload.
2. `CallbackService` looks up the transaction by `CheckoutRequestID`, updates status to `SUCCESS`, assigns reconciliation ID `REC-RBS789XYZ`, and publishes a `TransactionCompletedEvent` to RabbitMQ.
3. `TransactionEventConsumer` in the ERP Connector module picks up the event and dispatches it to the configured ERP adapter.

**URL:** `http://localhost:9090`

```promql

increase(payment_stk_initiated_count_total[1h])

histogram_quantile(0.95, rate(payment_callback_processing_time_seconds_bucket[5m]))
```

## 8. Troubleshooting & FAQs

### Q1: Flyway Migration Validation Error on Startup
* **Symptom:** `FlywayException: Validate failed: Migrations have failed validation`.
* **Cause:** A migration SQL file was modified after it was already applied to the database.
* **Fix:** Reset the development PostgreSQL volume and re-apply:
  ```bash
  docker compose down -v
  docker compose up -d
  ```

### Q2: Gateway Returns `403 Forbidden` on Callback Endpoint
* **Symptom:** `POST /api/v1/mpesa/callbacks/stk` returns `403 Forbidden`.
* **Cause:** `IpWhitelistFilter` blocks requests from IPs outside Safaricom's CIDR ranges (`196.201.214.0/24`, `196.201.213.0/24`).
* **Fix for Local Testing:** Add `127.0.0.1` or `0:0:0:0:0:0:0:1` (IPv6 loopback) to the whitelist in `openfloat-gateway/src/main/resources/application.yml`:
  ```yaml
  openfloat:
    gateway:
      safaricom-ip-whitelist:
        - 196.201.214.0/24
        - 196.201.213.0/24
        - 127.0.0.1/32        # Local testing
        - 0:0:0:0:0:0:0:1/128 # IPv6 loopback
  ```

### Q3: Staff Portal `npm install` or TypeScript Compilation Errors
* **Symptom:** Missing types for `@tanstack/react-query`, `recharts`, or `zod`.
* **Fix:** Run `npm install` inside the `openfloat-staff-portal` directory:
  ```bash
  cd openfloat-staff-portal
  npm install
  ```

### Q4: `401 Unauthorized` on All API Requests
* **Symptom:** Every request returns `HTTP 401` even with a Bearer token.
* **Cause:** The `openfloat-auth` service is not running, so JWT validation fails at the resource server.
* **Fix:** Ensure `openfloat-core` is started first (to run Flyway database migrations), followed by `openfloat-auth` (reachable at `http://localhost:8081` for JWKS key fetching) before accessing endpoints via `openfloat-gateway`.

### Q5: RabbitMQ `queue.erp.sync.dlq` Filling Up
* **Symptom:** Messages accumulate in the dead letter queue and are not processed.
* **Cause:** The configured ERP target endpoint is unreachable or returning errors after 5 retry attempts (1m → 5m → 25m exponential backoff).
* **Fix:**
  1. Check ERP target connectivity: `curl ${ERP_TARGET_URL}`.
  2. Inspect DLQ message headers for the exception: `kubectl logs -l app=openfloat-erp-connector | grep DLQ`.
  3. After resolving the root cause, re-drive messages via the Staff Portal or API:
     ```bash
     curl -X POST http://localhost:8080/api/v1/erp/redrive-dlq \
       -H "Authorization: Bearer ${ADMIN_TOKEN}"
     ```

### Q6: Daraja Token Refresh Failure (`DarajaTokenRefreshFailed` Alert)
* **Symptom:** STK Push and B2C requests fail with `502 Bad Gateway` after token expiration.
* **Cause:** Safaricom sandbox may be temporarily unavailable, or Daraja credentials are incorrect.
* **Fix:**
  1. Test Daraja connectivity directly:
     ```bash
     curl -v https://sandbox.safaricom.co.ke/oauth/v1/generate?grant_type=client_credentials \
       -u "${MPESA_CONSUMER_KEY}:${MPESA_CONSUMER_SECRET}"
     ```
  2. If credentials are valid but token is stale, force cache eviction:
     ```bash
     docker exec -it redis redis-cli DEL "daraja:access_token"
     ```

### Q7: Port Conflicts on Startup
* **Symptom:** `Address already in use: bind` on ports 8080, 8081, 8082, or 8443.
* **Fix:** Identify and kill the conflicting process:
  ```bash
  # Linux/macOS
  lsof -i :8080 | grep LISTEN
  kill -9 <PID>

  # Windows PowerShell
  netstat -ano | findstr :8080
  taskkill /PID <PID> /F
  ```

### Q8: Redis Connection Refused
* **Symptom:** `RedisConnectionException: Unable to connect to localhost:6379`.
* **Fix:** Ensure Redis is running: `docker compose up -d redis`. Verify with `docker compose logs redis`.
